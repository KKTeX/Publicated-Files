# 手書きの図を読むときの規則

手書きの図には、描き手の意図と、手の揺れ・描き直し・紙の歪みが混ざっている。TikZにするのは意図の方。

## 撮影・取り込みの状態を整える

- 斜めから撮った写真は台形に歪む。grid.py の `--clean` は回転(傾き)しか直さない。歪みが大きいときは、四隅を揃えて撮り直してもらうか、構造(行・列・同じ大きさの箱)から位置を決め、グリッドは相対位置の目安にだけ使う。
- 机や手、影が写っていたら `--crop` で紙の部分だけにする。
- 薄い鉛筆は `--clean` で濃くなる。それでも読めない部分は `--zoom` で拡大する。
- iPhone の HEIC はそのまま渡してよい(ImageMagick が読む)。読めなければ `magick in.heic in.png`(macOS なら `sips -s format png in.heic --out in.png` でも可)。

## 揃える(スナップ)

グリッドで読んだ値をそのまま使わず、次の順で丸める。

1. 同じ役割の要素は同じ大きさにする(箱の幅・高さ、円の半径、矢じり)。
2. 中心の x または y の差が 0.2〜0.3 cm 以内なら同じ値に揃える。行・列が見えるなら行列として配置する。
3. 間隔がほぼ等しい並びは等間隔にする。
4. 線は 0°・90°・45°、または図の中で繰り返し出てくる角度に寄せる。
5. 座標は 0.1 cm 単位(大きな図は 0.25 cm 単位)に丸める。
6. 接しているように見える線は、ノードの境界やアンカー(`(a.east)`、`(a.north)`)につなぐ。手書きで少し離れていても、つなぐ意図なら接続する。

7. 図の中の文字や本文が意味を決めているときは、許容幅を超えても意味に合わせる。例: 「最大速度」と書かれた点から下ろした破線 $t_1$ が頂点から 0.4 cm ずれている → 頂点の真下に揃える。直したことは報告に書く。

揃えると意味が変わる場合(わざとずらした配置、意味のある長さの違い、比率が問題の条件になっている幾何図形)は揃えない。

## 線の種類と記号を読む

- 実線と破線: 線が途切れ途切れでも、ペンのかすれか破線かを全体で判断する。補助線・境界・未確定の流れは破線が多い。
- 矢印: 矢じりの向きを必ず確認する。両端に矢じり(`<->`)、矢じり無しの線、二重線(`double`)を区別する。
- 曲線: 端点、極値(山・谷)、変曲点だけを拾い、単調な区間ごとに1本の `.. controls (p) and (q) ..` で描く。極値では接線が水平なので、制御点を極値と同じ高さに置く。
  - `to[out=..,in=..]` は2点をつなぐだけの簡単な弧なら手早い。ただし中継点で何本もつなぐと、区間ごとに曲率が変わるため継ぎ目に折れやこぶが出る。継ぎ目では前の区間の第2制御点と次の区間の第1制御点を、継ぎ目を挟んで一直線に置く。
  - 手書きの線上の点を十数個拾って `plot[smooth] coordinates {...}` に通すのは避ける。読み取り誤差がそのまま波打ちや折れになり、重ね合わせでは目立たなくても仕上がりで見える。
  - 関数の形が分かる(指数減衰、正弦波、放物線)なら `plot[domain=..] ({\x},{...})` で式として描く方がきれい。
- 塗り・斜線: 塗りつぶしは `fill=gray!25` 程度、斜線は `patterns.meta`。
- 囲み: 点線の大きな囲みはグループ表示。`fit` ライブラリで中のノードを囲む。
- 色ペン: 色は意味(強調、別系統、修正)として扱う。赤ペンの書き込みが「修正指示」なら、図に描くのではなく修正を反映する。判断がつかなければ利用者に聞く。

## 文字を読む

- 数式・記号は数式モードで書く。手書きの添字(x1 → $x_1$)、ハット・バー・ドット、ベクトル(太字か矢印かは文書の流儀に合わせる)、ギリシャ文字(α と a、ν と v、ε と ∈ の取り違えに注意)。
- 単位は立体(`\,\mathrm{m/s}`、siunitx が文書にあれば `\si{}` / `\unit{}`)。
- 和文・英文の表記は元図どおりにし、文書の用語と違う場合は文書に合わせるか確認する。
- 読めない字は推測で確定させない。`\node {??}` のままにせず、いったん最も可能性の高い読みで入れて `% TODO: 判読不明(候補: ...)` を付け、報告で確認する。
- 文字の大きさは揃える。手書きで大きく書いた見出しは `\bfseries` か少し大きくする程度にする。

## 余白と全体の大きさ

- 図全体の幅は手順0で決めた仕上がり幅に合わせる。手書きの紙面が余白だらけでも、図の部分だけを `--width-cm` の基準にする(1回目のグリッドで範囲を読み、`--frame` で図の部分だけにしてから作業する)。
- 文字が入る箱は、文字が収まる最小の大きさ(`minimum width`、`inner sep`)にし、手書きの箱が窮屈・過大でも整える。

## 曖昧な点の扱い

確信が持てない箇所は、作業を止めずに一番もっともらしい解釈で仕上げ、報告にまとめる。例:

- 「B→C の矢印は向きが判読しにくく、B→C としました」
- 「右下の記号は ε と読みました(∈ の可能性あり)」
- 「左の3つの箱は幅を揃えました」
